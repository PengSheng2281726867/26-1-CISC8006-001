- 原因：先建立独立 dot baseline，验证其实际前向和梯度与不可变官方快照一致。
- 改动：新增 src/paths.py 隔离进程缓存；独立实现原始共享投影、hop 缩放、LayerNorm、dot routing、squash 和分类头。
- 未改变：官方源码和工作树；dot agreement 数学；实际重复传播顺序。

所有后续重要版本必须在此追加原因、范围和验证结果，不覆盖主实验结果。

- 验证：重新执行基线一致性测试及新增 MLP/传播/梯度/隔离测试，证据保存至 results/ 下。

## v2_resource_reset（主实验组名 v2；数学与超参数保持 v1）

- 现象：v1 Pilot 的 24 次训练全部成功，但进程内 cuBLAS 缓存工作区令初始 GPU 分配从 Texas 首次约 1.4 MB 漂移至后续约 65.4 MB，不能直接把顺序造成的漂移解释为模型显存差异。
- 假设：持久化的实验进程内工作区没有被 empty_cache 回收。
- 修改：每次新训练前同步 GPU、回收 Python 对象，调用当前 PyTorch 提供的进程内 `_cuda_clearCublasWorkspaces()`，然后 empty_cache。补充异常后删除残留模型引用。没有更改任何模型、初始化、数据或训练超参数。
- 隔离：只清理本次 Python 进程拥有的工作区，不触碰其他项目或全局环境；v1 源码和 Pilot 结果保留，不覆盖。
- 验证：在独立 v2 组重新运行 24 次 Pilot，检查初始显存配对一致、梯度有效，并与 v1 对比权重/预测；通过后 Full 只使用 v2 协议。

### v2 验收通过

24/24 Checkpoint 重载核验通过；24 份训练后权重哈希与 v1 完全相同。成对初始显存差异最多 0.00928 MB，符合 MLP 新增参数存储量。MLP 有效梯度和参数变化、划分一致性、完成检测/损坏检测均通过。正式矩阵固定使用 v2，不继续修改模型或超参数。
